# Decision records

ADRs explain why the current design exists. They are maintained in place as
the design changes: fold replacement decisions into the relevant record and
delete decisions that no longer describe WT. Do not retain superseded records
or amendment chains as project history; Git retains that history.

Keep surviving ADR numbers stable when compacting and update links to removed
or renamed records. Assign new records unused numbers; gaps do not require
placeholder records or renumbering unrelated decisions. Accepted ADRs describe
shipped behavior; unshipped proposals belong in active work rather than this
directory.
